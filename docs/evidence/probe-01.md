## 二、确认待办指向指定接班人

- 创建测试待办（标题显式标"测试"，截止时间含时区）→ 回读详情：执行人 ID 精确指向指定接收人，创建人留痕，初始状态未完成。
- 结论：**待办可精确指向指定接班人，字段可回读，成立。**

## 三、确认操作者身份可回读

- 将测试待办标记完成 → 回读：完成状态与完成时间落值；活动流水逐条记录 `创建`/`完成` 动作，每条均带操作者内部 ID。
- 结论：**渠道本身不拦"错人"，但完整记录"谁做的"；"错人不放行、无关联单据不放行"由业务层凭此留痕强制执行，能力基础成立。**

## 四、提醒送达

- 以登录人身份向指定接收人单聊发送测试文本（带幂等键）→ 查发送状态：`SUCCESS`，消息 ID 与会话 ID 可回读。
- 结论：**提醒可送达指定人且发送状态可查，成立。**

## 五、清理与回读

- 测试待办已删除：详情接口回读"任务不存在"，列表复查为 0。测试消息发给自己、内容显式标"测试"，无法撤回但无扰他。

## 六、错人场景实测（2026-09-20 补测，第二人配合）

- 方法：主控创建一条**仅指派自己**的测试待办（回读核实执行人唯一）；请第二协作者在钉钉中独立验证两点并回复。
- 结果：① 协作者在自己的待办列表与搜索中均**看不到**该测试单；② 直接打开该待办详情链接返回**无权限**（渠道原话：task not exist or operator not in task）。
- 结论：**渠道级"错人不放行"成立**——待办按执行人严格隔离，非执行人不可见、不可操作；业务层"无关联单据不放行"可在此基础上叠加强制。
- 清理：删除前后均回读核实（删除前原始态完好 isDone=false、执行人唯一；删除后回读"任务不存在"）。
